# Phase 4 人間による実操作テスト

作成日: 2026-10-07。対象は[Phase 4 の承認済み要求](../requirements/phase-4-web-api.md)と[Definition of Done](../development/definition-of-done.md)。この文書は実施手順と判定基準であり、**実施結果ではない**。Simulator または実機の画面・設定・入力操作は人間が行い、結果を記録する。Swift Testing / XCTest の結果とは分けて扱う。

## 準備

1. Phase 4 のビルドを iPadOS 17 以降の iPad Simulator または iPad 実機で起動する。端末名、iPadOS、ビルドの commit、実施日を末尾の記録欄に書く。可変ウインドウ幅は対応する iPad / Simulator で確認する。
2. 通信できる状態で、テスト用 Project を2つ作る。例: `手動確認A` と `手動確認B`。A に Note を1件作り、既存の Note が後で残っていることを見られるようにする。既存の実データを消去しない。
3. A を選び、Note 一覧上部の「Webで文献を検索」を開く。検索画面の「保存先: 手動確認A」と「検索語はCrossrefへ送信されます。」を確認する。外部へ送ってよい一般的な検索語を使う。
4. 「文献を検索」に検索語を入力し、「検索」を押す。結果がなければ別の一般的な語で試す。表示された1件のタイトル、DOI、出典URLを記録する。Crossref 側の検索結果は変動するため、特定の文献が必ず返ることは合格条件にしない。
5. 設定を変えるテストでは、変更前の画面と Project を記録する。各ケースの終了後は元の表示設定へ戻してよい。外部サイトを開いた後はアプリに戻る。

## ケースと判定基準

### M-01 通常操作、保存、重複、再起動

1. 準備の検索結果でタイトル、DOI、HTTPS の出典URLを確認し、「Projectに保存」を押す。
2. 「このProjectに保存しました」を確認して検索画面を閉じる。A の Note 一覧の「Web Resources」に選んだ文献があり、Note も残っていることを確認する。文献を開き、出典へ移動できることを確認する。
3. 同じ Project と検索語で同じ DOI を再度選び、「Projectに保存」を押す。「同じDOIの保存済み項目を表示しています」を確認し、A の一覧に同じ DOI が1件だけあることを確認する。
4. アプリを終了・再起動し、A の Note と保存済み文献が残ること、B にはその文献が表示されないことを確認する。

**合格:** 保存先、外部送信、文献情報が分かる。A だけに保存され、同じ DOI の重複がなく、再起動後も Note と文献を参照できる。

### M-02 可変ウインドウ幅

1. A を開き、フルスクリーンで Project、Note、Web Resource の一覧と「Webで文献を検索」「Noteを追加」への到達を確認する。
2. 対応する iPad で Stage Manager などのウインドウ表示を使い、アプリを広い幅から狭い幅へ、次に広い幅へ戻す。ウインドウ操作が使えない環境では、使用した代替条件（例: 横向き・縦向き）を記録し、可変幅自体は未確認とする。
3. 各幅で A の検索画面を開き、保存先、検索語入力、検索ボタン、結果のタイトル・DOI・URL、保存ボタン、閉じるボタンを確認する。Project 切替と Note 一覧へ戻る操作も行う。

**合格:** 狭い幅でも主要操作へ到達でき、文字やボタンが重なって操作不能にならず、ウインドウ幅を戻しても A の保存データと選択状態が破損しない。

### M-03 Light / Dark Mode と色以外の手掛かり

1. iPad の「設定」→「画面表示と明るさ」で「ライト」「ダーク」を順に選び、各状態で A の検索画面と保存済み一覧を開く。
2. 検索結果、保存後の通知、検索エラーが出た場合の「検索できませんでした」と「再試行」、保存済みリンクの文字を確認する。エラーを再現できなければ、その箇所は未確認として記録する。

**合格:** 両モードで文字・ボタン・入力欄・リンクが判読できる。成功・失敗・選択状態の意味が色だけに依存せず、文言やアイコンでも分かる。

### M-04 Dynamic Type

1. 「設定」→「アクセシビリティ」→「画面表示とテキストサイズ」→「さらに大きな文字」を開き、大きなアクセシビリティ用文字サイズを有効にする。選んだサイズを記録する。
2. A の検索画面で保存先、外部送信の説明、検索語入力、検索ボタン、結果のタイトル・DOI・URL、保存ボタンを順に確認する。
3. 検索画面を閉じ、Note 一覧の「Web Resources」と保存済みリンクを確認する。必要ならスクロールして操作する。M-02 の狭い幅と組み合わせられる場合はその状態も確認する。

**合格:** 主要テキストを読め、ボタンや入力欄を操作できる。文字の重なり・切れによって検索、保存、再参照が妨げられない。

### M-05 VoiceOver

1. 「設定」→「アクセシビリティ」→「VoiceOver」をオンにする。A を選び、スワイプで要素を移動し、ダブルタップで起動する。
2. 「Webで文献を検索」を開き、保存先、外部送信の説明、検索欄、検索ボタンを読み上げで確認する。検索結果のタイトル、DOI、URL、保存ボタンを順にたどり、保存する。
3. 検索画面を閉じ、A の「Web Resources」にある保存済み文献をたどる。出典を開く操作と、Note へ戻る操作を確認する。

**合格:** 操作の目的と保存先が読み上げで分かり、検索→保存→保存済み出典への移動を視覚だけに頼らず完了できる。意味のない重複読み上げや到達できない主要操作がない。

### M-06 外部キーボード

1. 外部キーボードを接続する。必要に応じて iPad の「設定」→「アクセシビリティ」から「フルキーボードアクセス」をオンにする。設定名が異なる場合は設定内検索で探す。
2. Tab / Shift-Tab で Project、Note 一覧、「Webで文献を検索」、検索欄、検索ボタン、「Projectに保存」、「閉じる」へ移動し、Space または Return で操作する。利用したキーと到達できた操作を記録する。
3. 検索欄に文字を入力し、Return で検索できることを確認する。既存の「Noteを追加」が引き続き到達可能なことも確認する。

**合格:** タッチなしで主要フローへ到達し、検索と保存を行える。フォーカス位置が分かり、操作中に行き止まりにならない。特定のショートカットを要求するケースではない。

### M-07 検索状態と中断の目視確認

1. 検索ボタンを押した直後に「検索中」が表示されるか観察する。通信が速く観察できなければ未確認として記録する。
2. 検索語を変更して再検索する。古い検索結果が新しい語の結果として残らないことを確認する。通信中に画面を閉じた場合、通常の検索エラーが表示されないことを確認する。
3. ネットワークを一時的に切り、検索エラーの文言と「再試行」を確認する。ネットワークを戻して再試行する。通信事業者や Crossref の状態に左右されるため、再現できない場合は未確認とする。HTTP エラーと不正 JSON は自動テストで確認済みであり、手動で無理に再現しない。

**合格:** 観察できた状態では、読み込み・結果なし・エラーが区別され、再試行できる。古い結果やキャンセルを通常のエラーとして見せない。
